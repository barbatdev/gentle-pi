# feat(peers): add transport-neutral authenticated delivery core

## Parent and status gate
Parent: `https://github.com/Gentleman-Programming/gentle-pi/issues/442`. This draft is not approved or implementation-ready. B1, B2a, and B2b1 must be created, formally linked, reviewed, and accepted before implementation. B2b2 consumes the bounded invalidated-epoch hooks defined here; no joint-review or circular dependency exists.

## Outcome
Provide the platform-neutral authenticated delivery core that owns canonical-envelope admission, the sole wire ACK transition table, dedupe, bounded process-local queues, and receiver-turn admission before POSIX or Windows transport integration.

## Evidence and scope
Platform endpoints need one shared, deterministic delivery authority, while B2b2 needs a bounded way to apply credential invalidation after B2b1 decides rotation or revocation. This slice accepts an already platform-authenticated source context and a canonical envelope; it defines no endpoint or platform lifecycle.

## Included scope
- A transport-neutral input boundary for an already authenticated source context plus the canonical envelope.
- Exact envelope/MAC-or-signature binding, terminal wire ACK authority, dedupe, queue admission, limits, and one-turn dispatch state.
- Bounded B2b2 invalidated-epoch hooks over this slice's admission, queue, and turn state.

## Non-goals
No platform endpoint, transport framing, liveness, shutdown integration, trust or credential mutation, UX, durable mailbox/history, cross-machine delivery, automatic retry, or receiver-tool privilege expansion.

## Normative contract
The B6c or B6d integration supplies the combined immutable B6a source context containing exactly authenticated source peer ID, authenticated target peer ID, credential protocol epoch, credential revocation generation, `lane_id`, `lane_admission_generation`, `handoff_lease_id`, and opaque successful platform-authentication binding. B4a and B5a still own only platform-authentication context. Before calling B6a, B6c or B6d acquires exactly one B6b1 handoff lease and combines its exact immutable lane identifiers with that B4a or B5a context. It must not supply a mutable trust, credential, lane, or lease decision. The core accepts exactly this combined context and a canonical envelope with fields exactly `source`, `target`, `protocol_epoch`, `message_id`, `nonce`, `issued_at`, `expires_at`, `trace_id`, `trace_depth`, `hop_count`, and `MAC/signature`.

`source`, `target`, and `protocol_epoch` must equal the corresponding authenticated context values. The MAC/signature binds the authenticated source peer ID, authenticated target peer ID, credential protocol epoch, and every canonical-envelope field, in canonical field order. The core rejects a missing, malformed, or mismatched binding. The model and envelope cannot supply or override any combined-context field. Platform adapters may authenticate the binding but may not emit wire ACKs, reserve dedupe, admit queues, start receiver turns, or create lane or lease identities.

B6a is the sole wire ACK authority. B2b2 owns credential/revocation decisions and synchronously updates only B6a's credential-authorization projection through its existing hook; it never mutates or calls B6b1 lane state. B6b1 solely owns lane SPI state, generation, leases, and lease authority. On registration or closure, B6b1 synchronously publishes a version-bound read-only lane-admission projection to B6a; B6a owns that projection and checks it but never mutates lane state. B6a also checks B6b1-issued lease authority read-only and never creates, transfers, releases, or treats a lease as accepted-work capacity or delivery authority. B6b1 opens a registered lane only after B6a publishes its open projection. For closure, B6b1 first atomically closes and increments B6a's lane projection so stale commits are rejected, then marks its lane closing and drains leases; a publication failure is fail-closed. B6a evaluates each request in one serialized admission transaction and freezes this order:

0. Safely parse canonical structure and the hard bounds needed for evaluation. Malformed input is `rejected`.
1. Validate the immutable combined context, trust and current credential revocation generation, MAC/signature, source/target/epoch, nonce, hop/trace, and rate-input shape. Check `lane_id`, `lane_admission_generation`, and `handoff_lease_id` against B6a's current lane-admission projection and B6b1-issued lease authority, and check the credential projection. Atomically recheck credential revocation generation and lane admission generation at commit. An unknown, stale, mismatched, closing, closed, or unreleased-invalid lease or context is `rejected`; B2b2 credential-projection invalidation and separately B6b1 lane-projection closure linearize here.
2. If expiry is reached, return `expired`.
3. If the exact dedupe key exists within 10 minutes, return `duplicate`.
4. If atomic rate or outstanding accepted-work capacity admission cannot succeed, return `queue_full` without a dedupe reservation.
5. Atomically reserve dedupe, the local queue record, and one outstanding capacity token for the authenticated peer plus one for the receiver, then return `accepted`.

Thus malformed or security-invalid input beats every other result; revoked-plus-duplicate is `rejected`; expired-plus-duplicate is `expired`; and a valid duplicate beats capacity or rate exhaustion. `rejected`, `expired`, `duplicate`, and `queue_full` make no state change. The dedupe key is exactly `(protocol_epoch, authenticated_source_peer_id, authenticated_target_peer_id, message_id)` and its retention is exactly 10 minutes. Enforce every B1 limit exactly: UTF-8 message at most 16 KiB; 32 outstanding accepted-work entries per authenticated peer; 128 outstanding accepted-work entries per receiver; burst 5; 30 accepted messages per source-target pair per minute; hop count 4; trace depth 4; expiry at most 5 minutes; and dedupe retention 10 minutes.

After `accepted`, B6a owns exactly `queued -> dispatching -> enqueued -> running -> terminal`, with permitted direct terminal paths. Its only internal terminal dispositions are `host_settled`, `delivery_outcome_unknown`, `revoked_before_delivery`, `revoked_during_turn`, `shutdown_before_delivery`, and `shutdown_during_turn`. One immutable terminal CAS succeeds exactly once. The per-peer and receiver capacity tokens remain counted through queued, dispatching, enqueued, running, cancellation-pending, and outcome-unknown quarantine; dispatching never releases capacity. Release each token exactly once only when Pi can no longer execute the entry: a pre-handoff revoked/shutdown terminal, exact correlated `host_settled`, exact correlated revoked/shutdown abort that reaches `agent_settled`, normal enqueued-no-start `agent_settled` as `delivery_outcome_unknown`, or session teardown for a throw/ambiguous no-correlation `delivery_outcome_unknown` quarantine. A throw or ambiguous enqueue fixes the immutable terminal disposition as `delivery_outcome_unknown`, creates no retry, and retains its quarantined token until session teardown unless exact correlated settlement proves no pending work. Dispatch and turn correlation releases exactly once on terminal. Dedupe retention stays independent for 10 minutes and never starts another turn.

B2b2 credential-projection updates and B6b1 lane-projection publication participate only in admission step 1. A matching `queued` or pre-call `dispatching` entry terminalizes as `revoked_before_delivery`; shutdown uses `shutdown_before_delivery`; either pre-handoff terminal releases its outstanding capacity token exactly once. Once `pi.sendUserMessage` returns, `enqueued` means Pi owns the queued user entry. Pi 0.84.3 exposes no selective removal of that exact queued `sendUserMessage(...,{deliverAs:'followUp'})` entry, so invalidation marks it cancellation-pending with eventual `revoked_during_turn` and shutdown marks it cancellation-pending with eventual `shutdown_during_turn`; neither claim zero model turn. Enqueued and running entries retain their capacity tokens through cancellation and abort requests. An exact correlated `before_agent_start` rechecks B6a's credential-authorization and lane-admission projections before provider or tool work. If invalidated or shutdown-pending, B6b1 activates deny-all, requests one abort for that exact correlated peer run, permits no tool execution, and retains the during-turn disposition. Exact correlated `agent_settled` terminalizes a pending enqueued entry with that pending disposition when it never starts and releases its token; an exact correlated aborted running settlement likewise releases its token. A normal nonpending enqueued entry with no start becomes `delivery_outcome_unknown` only at exact correlated `agent_settled`, then releases its token. Every current-generation peer-tool authorization rechecks B6a state. A prior `accepted` ACK is never replaced or supplemented. B6a retains ACK, dedupe, queue, state, terminal-CAS, and both admission projections; B2b2 retains only invalidation decisions and credential-projection publication; B6b1 retains lane SPI state, leases, guarded host dispatch, and lane-projection publication; B6c and B6d retain platform integration and request matching lane closure for endpoint lifecycle.

## Dependencies
Parent `https://github.com/Gentleman-Programming/gentle-pi/issues/442`; B1 limits and threat model; B2a verified trust records; and B2b1 current credential state, rotation, and invalidated-epoch events. B2b2 consumes this completed core; B4a/B5a consume its envelope contract; B4b1/B5b1 consume its invalidation hooks; B6b1 consumes queue/turn dispatch state; B6c and B6d integrate completed platform paths; B7 consumes B6a/B6b1 only through an explicitly registered B6c or B6d lane.

## Acceptance criteria
- [ ] The exact eight-field combined B6a source context, canonical envelope fields, MAC/signature binding, credential projection, B6a lane-admission projection, and B6b1-issued lease-authority checks are validated before queue admission; model or envelope input cannot supply or override the context.
- [ ] The serialized precedence produces `rejected`, `expired`, `duplicate`, `queue_full`, or `accepted` exactly as specified, including malformed/security-invalid, revoked-plus-duplicate, expired-plus-duplicate, valid-duplicate-plus-capacity, and admission-race cases.
- [ ] The exact dedupe key and independent 10-minute retention prevent duplicate receiver turns; reservation and queue admission are atomic.
- [ ] Every B1 limit, outstanding accepted-work capacity bound across every accepted lifecycle state, unknown-outcome quarantine retention, and at-most-one receiver turn is regression-tested.
- [ ] `queued -> dispatching -> enqueued -> running -> terminal`, direct terminal paths, one terminal CAS, exact dispositions, no capacity release on dispatching, exact correlated or teardown-only capacity release, correlation release, and no-new-turn dedupe retention are proven; `enqueued` is not selectively removable after Pi handoff, while pending revocation or shutdown is terminalized as the matching during-turn disposition.
- [ ] B2b2 owns only credential/revocation generation and synchronous credential-projection publication, while B6b1 owns only lane SPI state, lease lifecycle, lease authority, and synchronous lane-projection publication; B6a atomically checks both read-only projections and the issued lease without either upstream authority calling the other or taking ACK, dedupe, queue, state, terminal-CAS, accepted-work capacity, or delivery ownership.
- [ ] No platform endpoint, lifecycle integration, credential/trust mutation, UX, durable mailbox, cross-machine delivery, or retry is introduced.

## Verification
Deterministic-clock tests for every ACK transition and B1 limit; canonical-binding and malformed-context tests; no-lease and wrong-lane, wrong-generation, wrong-lease, stale-lease, and unknown-lease rejection tests; overlap and race tests for revoked-plus-duplicate, expired-plus-duplicate, valid-duplicate-plus-capacity, credential projection, lane-projection closure, lease/projection closure, and atomic admission; dedupe/one-turn tests; state, terminal-CAS, no-dispatching-release, all-state outstanding-capacity, unknown-quarantine retention, exact-settlement, teardown-release, and correlation-release tests; B2b2 invalidation tests for accepted-before/rejected-after, pre-handoff terminalization/no-new-ACK, enqueued cancellation-pending without selective dequeue, exact correlated deny-all and one peer-only abort, pending settlement, running abort, and current-generation denial; B6b1 lane publication ordering and lease-authority tests; human/unrelated and text/no-pending no-abort fixtures; and affected package tests.

## Rollback
Disable the transport-neutral admission core without migrating queued entries, emitting new ACKs, retrying through another authority, or changing B2b2's credential invalidation decision.
